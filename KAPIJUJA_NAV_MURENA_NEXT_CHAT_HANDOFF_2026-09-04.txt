4. BUILD / SIGNING / UPDATE INSTALL
==================================================

Workflow:
.github/workflows/build-stock-murena-apk.yml

The CI build follows Murena's Android/Rust environment and generates Rust/UniFFI before the Android build.

A stable Kapijuja CI debug signing keystore is used for the .debug application and GitHub run data is used for a monotonically increasing versionCode.

Why this matters:
older CI runs could use an ephemeral Android debug key, so Android refused to install a new APK as an update over an old one even though a clean install worked.

One clean install can be required when migrating away from the old ephemeral signature. After that, builds signed by the stable Kapijuja debug key should update in place.

Do not mix the debug signing identity with a future release signing identity.

5. API KEYS / STADIA / TRAFFIC
==================================================

The APK should NOT require the private project Stadia key compiled into the binary.

Advanced Settings exposes Valhalla/Pelias URL + key configuration.

Behavior:
- fresh/default install uses the upstream no-key defaults;
- user may enter a Stadia key manually;
- entering the Stadia key selects the Stadia endpoint where appropriate;
- Reset API settings to defaults removes user URL/key overrides and returns to the fresh-install no-key defaults.

The same configured Valhalla key path is used for ordinary routing and traffic routing. There is no separate traffic key.

The real project key was safely tested in GitHub Actions without printing it.

Confirmed accepted premium profiles:
- auto_traffic_premium -> HTTP 200
- bus_traffic_premium -> HTTP 200
- truck_traffic_premium -> HTTP 200 on a known routable Truck segment

Traffic requests use current-departure semantics.

Traffic fallback:
if an eligible hosted traffic profile is rejected as unsupported/unauthorized, routing can retry the corresponding non-traffic profile instead of failing the entire route.

Closures:
ignore_closures is not enabled by default. Existing backend/graph closure information is intended to be respected.

NOT IMPLEMENTED YET:
country-specific EU National Access Point / NAP closure adapters. That is future work.

6. TRUCK ROUTING
==================================================

The original stock bug:
DirectionsViewModel sent RoutingMode.TRUCK to ordinary Driving because the mode selector fell through to the default driving wrapper.

Fixed:
Truck now uses the dedicated Truck Ferrostar wrapper and Truck Valhalla costing.

Built-in Truck defaults:
- length 16.5 m
- width 2.5 m
- height 4.0 m
- weight 45 t
- axle count 3
- use_truck_route 1.0
- use_highways 0.8
- use_living_streets 0.0
- use_tracks 0.0
- avoid unpaved
- service/low-class penalties
- closures/restrictions/oneways/access not globally ignored

Truck destination correlation:
100 m legal-edge candidate radius.

Reason:
a destination coordinate can lie on the nearest road edge that is forbidden to Truck. The 100 m correlation radius lets Valhalla choose a nearby legal Truck edge instead of returning NoRoute.

Truck cautionary final approach:
kept conservative, roughly max 120 m actual routed distance.

Do not globally set ignore_restrictions for Truck.

10. DASHED FINAL APPROACH — CURRENT BUS LOGIC
==================================================

Main route:
always try the strict Truck/Bus/Coach profile first.

If strict routing reaches only a nearby legal heavy-vehicle edge and the exact destination requires a cautionary approach, build a second final-approach route.

Bus final approach max:
600 m ACTUAL ROUTED DISTANCE.

Not just straight-line distance.

The Bus fallback is tiered.

TIER 1 — YELLOW DASHED
ACCESS_ONLY

- AUTO access semantics
- ignore_access=true
- configured length retained
- configured width retained
- configured height retained
- configured weight retained
- ignore_restrictions=false
- ignore_oneways=false
- ignore_closures=false

This is the preferred fallback.

TIER 2 — ORANGE DASHED
WEIGHT_RELAXED

Only if Tier 1 cannot route.

- access restriction softened as above
- effective weight set to 0.0 for restriction matching
- length retained
- width retained
- height retained
- one-way and closure logic retained
- ignore_restrictions still false

Purpose:
some city-center roads can have map weight restrictions that do not reflect practical local/coach access.

TIER 3 — RED DASHED
WEIGHT_AND_LENGTH_RELAXED

Only if Tier 1 and Tier 2 both fail.

- effective weight = 0.0
- effective length = 0.0
- REAL width retained
- REAL height retained
- one-way retained
- closures retained
- ignore_restrictions=false

Purpose:
last-resort city-center approach where mapped max-length (for example 7.5 m) would otherwise block a real full-size coach route.

NEVER relax:
- width
- height

Those must remain real Bus dimensions in every fallback tier.

The user explicitly wants the driver to make the final visual judgment on the street when the route is shown as cautionary dashed access.

Current limitation to remember:
the dashed approach is a separately calculated route/overlay. If future testing shows that the last 50-600 m need full independent spoken maneuver/TTS state-machine guidance, that is a separate enhancement. Do not assume it is already equivalent to the primary Ferrostar route state.

==================================================

Observed problem:
Valhalla can choose a residential road through a housing estate even when a nearby wide arterial is much more suitable for a 13.5 m coach.

Current mitigations:
Truck:
- use_truck_route
- low_class_penalty
- service penalties
- highway preference
- living-street/track avoidance

Bus/Coach:
- service penalty/factor
- alley factor
- highway preference
- living-street/track avoidance
- maneuver penalty
- real dimensions

Do NOT invent a fake lanes>=2 Valhalla parameter. There is no clean standard option for that in the current costing.

If the real-device route is still bad:
inspect the exact OSM tags of that road first.
Parked cars and swept-path turning geometry are not automatically known to Valhalla unless represented by map data/restrictions/incidents.

15. STADIA JSON SCHEMA FIX
==================================================

Real hosted Stadia diagnostics found that some second-based routing penalties/costs must be JSON integers.

Example:
300.0 could be rejected where 300 is accepted.

RoutingOptions.toValhallaOptionsJson() now normalizes known second-based costs/penalties to JSON integer values at the API boundary.

Do NOT round:
vehicle length, width, height or weight as part of this integer-cost normalization.
